Meshes and Materials

pixi-solid-3d provides <Mesh3D> to render 3D geometry combined with materials.

Four geometries and all four material types, on a turntable:

In 3D rendering engines like PixiJS 3D, GPU resources (buffers, textures, and shader pipeline descriptors) are expensive to allocate. pixi-solid-3d gives you two ways to work with geometries and materials:

  1. Declarative Nested Components (Recommended for component-scoped resources): Material options stay live, and the resource is disposed automatically on unmount.
  2. Instantiated Object Props (Recommended for shared / global resources): Pass pre-created class instances where you retain ownership and manage lifecycle.

1. Declarative Nested Components (Automatic Disposal)

Section titled “1. Declarative Nested Components (Automatic Disposal)”

When geometries and materials are placed as direct JSX children of <Mesh3D>, pixi-solid-3d manages their lifecycle for you. When the component unmounts or conditionally swaps, it calls .destroy() automatically.

Furthermore, updating properties like roughness, metallic, or baseColor updates the existing GPU material directly with zero allocations.

Changing size, and changing shape

Section titled “Changing size, and changing shape”

A geometry’s options are read when it is built — @pixi/3d turns them into vertex buffers and keeps no settable copy — so changing a geometry option after mount does not reshape it. Materials are the opposite: their options are live fields, so <Material3D roughness={roughness()} /> follows the signal.

To make something bigger, scale the mesh. That is a transform, so it costs nothing and updates every frame:

To change the shape itself — segments, radius, a different geometry altogether — mount a new geometry. Inside <Mesh3D>, <Show keyed> remounts it and disposes the old one:

Scaling is not always equivalent: anything that reads vertex positions, such as the dissolve bit’s holes, works in the geometry’s stored units and therefore scales with the mesh. Those need a rebuilt geometry, which is why the two are separate operations.

2. Instantiated Object Props (Resource Sharing)

Section titled “2. Instantiated Object Props (Resource Sharing)”

If you have a geometry or material that is shared across hundreds of meshes (e.g., enemy particles, terrain tiles, or trees in a forest), you should create a single instance outside the component tree and pass it as a prop.

When passed as a prop, pixi-solid-3d treats it as user-owned and will never destroy it when an individual mesh unmounts:

Summary of Lifecycles

Section titled “Summary of Lifecycles”
Usage Pattern Syntax Who Owns Cleanup? When is it Destroyed?
Nested JSX Child <Mesh3D><CubeGeometry /><Material3D /></Mesh3D> pixi-solid-3d Automatically on unmount / condition change
Direct Prop <Mesh3D geometry={geom} material={mat} /> Caller / Application When caller manually calls geom.destroy()

Available Declarative Geometries

Section titled “Available Declarative Geometries”
  • <CubeGeometry width={...} height={...} depth={...} />
  • <SphereGeometry radius={...} widthSegments={...} heightSegments={...} />
  • <PlaneGeometry width={...} height={...} /> — lies in XY with a +Z normal, so a quarter turn on X makes it a floor
  • <CylinderGeometry radiusTop={...} radiusBottom={...} height={...} />
  • <ConeGeometry radius={...} height={...} />
  • <CapsuleGeometry radius={...} height={...} />
  • <TorusGeometry radius={...} tube={...} />
  • <TorusKnotGeometry radius={...} tube={...} />
  • <IcosahedronGeometry radius={...} />

Available Declarative Materials

Section titled “Available Declarative Materials”
  • <Material3D baseColor={...} roughness={...} metallic={...} normalTexture={...} /> — PBR metallic-roughness material.
  • <FlatMaterial baseColor={...} baseColorTexture={...} /> — Unlit flat color or texture.
  • <PhongMaterial baseColor={...} specularColor={...} shininess={...} /> — Classic Blinn-Phong material.
  • <ToonMaterial baseColor={...} bands={...} outline={...} /> — Cel-shaded stylized toon material.
