For applications with many assets, managing individual asset loading can become cumbersome.
PixiJS provides an **Asset Manifest** system that lets you define all your assets, their paths, and groups in a single JSON file.

Use PixiJS [AssetPack](https://pixijs.io/assetpack/) to generate the manifest for you.

This guide demonstrates how to load an entire asset manifest and then access the loaded assets within your `pixi-solid` application.

## What is an Asset Manifest?

An asset manifest is a JSON file that describes your application's assets. It typically includes:

- **`bundles`**: Groups of assets that can be loaded together. This is extremely useful for loading assets required for a specific scene or component.
- **`assets`**: Individual assets with their unique `alias` (how you refer to them in code) and `src` (their file path).

### Example `assets-manifest.json`

Let's assume you have an `assets-manifest.json` file in your `public` folder like this:

```json
{
  "bundles": [
    {
      "name": "game-assets",
      "assets": [
        {
          "alias": "background",
          "src": "/assets/background.png"
        },
        {
          "alias": "player_idle",
          "src": "/assets/player_idle.png"
        },
        {
          "alias": "coin",
          "src": "/assets/coin.png"
        }
      ]
    },
    {
      "name": "ui-assets",
      "assets": [
        {
          "alias": "button_play",
          "src": "/assets/button_play.png"
        },
        {
          "alias": "font_pixel",
          "src": "/assets/pixel_font.fnt"
        }
      ]
    }
  ]
}
```

Loading a manifest resolves to `void`, so the memo reports when the bundles are ready rather than returning the assets. Components then read each asset by its alias as they need it.

### Example: Loading Assets from a Manifest

```tsx
import type * as Pixi from "pixi.js";
import { Assets } from "pixi.js";
import { PixiCanvas, Sprite, Text } from "pixi-solid";
import { createMemo, Loading, Show } from "solid-js";

export const AssetManifestLoadingDemo = () => {
  const assetsReady = createMemo(async () => {
    // 1. Register the manifest
    await Assets.init({
      manifest: "/assets-manifest.json",
    });

    // 2. Load the bundles this scene needs
    await Assets.loadBundle("game-assets");
    await Assets.loadBundle("ui-assets");

    // `Assets.init` and `loadBundle` resolve to void, so return true to open the gate.
    return true;
  });

  return (
    // The fallback is a DOM element, so the boundary sits outside the canvas. A `<Loading>`
    // inside `PixiCanvas` would add its fallback as a Pixi child.
    <Loading fallback={<p>Loading...</p>}>
      {/* `Show` supplies the read the boundary waits on, then renders once the assets are ready */}
      <Show when={assetsReady()}>
        <PixiCanvas>
          {/* Read assets by the alias the manifest defines */}
          <Sprite
            texture={Assets.get<Pixi.Texture>("background")}
            anchor={0.5}
            position={[400, 300]}
            scale={0.8}
          />
          <Sprite
            texture={Assets.get<Pixi.Texture>("player_idle")}
            anchor={0.5}
            position={[400, 300]}
          />
          <Sprite texture={Assets.get<Pixi.Texture>("coin")} anchor={0.5} position={[450, 250]} />
          <Sprite
            texture={Assets.get<Pixi.Texture>("button_play")}
            anchor={0.5}
            position={[400, 450]}
          />
          <Text
            text="Game Loaded!"
            style={{ fontFamily: "font_pixel", fontSize: 32, fill: 0xffffff }}
            position={[200, 50]}
          />
        </PixiCanvas>
      </Show>
    </Loading>
  );
};
```

The boundary renders its `fallback` while the bundles load, so the page can show a DOM loading indicator before any Pixi object exists.

When a scene needs only a few known assets, return them from the memo and read them directly instead. See [loading individual assets](../individual-assets).
