`pixi-solid-3d` extends `pixi-solid` with declarative SolidJS components for PixiJS 3D scenes powered by `@pixi/3d`.

### Installation

Add the 3D package and the 3D engine to your project:

```bash
pnpm add pixi-solid-3d @pixi/3d
```

`@pixi/3d` 0.1.0 needs `pixi.js` 8.23.0 or later. `pixi-solid-3d` declares `@pixi/3d >=0.1.0 <0.2`
as a peer, so both packages must be upgraded together.

These steps assume `solid-js`, `pixi.js`, and `pixi-solid` are already installed. See
[Project setup](/getting-started/project-setup) if they are not.

### How 3D works in PixiJS

In PixiJS v8, 3D scenes are hosted inside a 2D viewport container called `View3D`.

- `<View3D>` is a 2D PixiJS display node that you can place inside `<PixiCanvas>` or anywhere in your 2D scene graph.
- Children placed inside `<View3D>` are automatically attached to its 3D root (`view.root`, a `Container3D`).
- Inside the 3D scene, you can place 3D containers (`<Container3D>`), meshes (`<Mesh3D>`), models (`<Model3D>`), lights (`<DirectionalLight>`, `<PointLight>`, `<AmbientLight>`), and interactive camera controls (`<OrbitCamera>`).

### Viewport ownership

A `View3D` can only be a 2D display node, so it cannot also contain 2D siblings. To render 2D HUD
or UI elements on top of the 3D scene, those elements must be mounted _beside_ the viewport and
share its `View3D` instance. `<View3DProvider>` does exactly that: it **creates and owns** the
`View3D` and shares it through context, and a `<View3D>` beneath it mounts that instance into the
2D scene graph.

```tsx
<View3DProvider width={800} height={600} toneMapping="aces">
  {/* Mounts the provider-owned View3D and holds the 3D scene */}
  <View3D>
    <Camera3D z={6} />
    <Mesh3D geometry={geometry} material={material} />
  </View3D>

  {/* 2D sibling — resolves the same View3D from context */}
  <HealthBar />
</View3DProvider>
```

Both `<View3D>` and `<View3DProvider>` resolve their instance the same way:

| Case                                 | Who creates the `View3D` | Who destroys it    |
| ------------------------------------ | ------------------------ | ------------------ |
| `<View3D>` on its own                | `<View3D>`               | `<View3D>`         |
| `<View3DProvider>` on its own        | `<View3DProvider>`       | `<View3DProvider>` |
| `<View3DProvider as={view}>`         | you                      | nothing            |
| `<View3D as={view}>`                 | you                      | nothing            |
| `<View3D>` inside `<View3DProvider>` | the provider             | the provider       |

Because the provider owns the instance, every `View3DOptions` prop belongs on the provider rather
than on the `<View3D>` that mounts it. In development, passing options to a `<View3D>` inside a
`<View3DProvider>` logs a warning telling you to move them up. Use `as` on the _provider_ to adopt
a `View3D` you created yourself; combining `as` with a provider throws. For multiple viewports
(split-screen, minimap PIP), use one provider per viewport.
